### Performance (synthetic site, `fork/scripts/perf-500.ts`, no sidecar, no LLM)

| Pages | Wall   | Peak RSS | Peak heap |
| ----- | ------ | -------- | --------- |
| 10    | 0.36 s | 287 MB   | 104 MB    |
| 100   | 0.76 s | 309 MB   | 86 MB     |
| 250   | 1.0 s  | 302 MB   | 117 MB    |
| 500   | 1.6 s  | 349 MB   | 110 MB    |
| 1000  | 2.8 s  | 388 MB   | 151 MB    |

- At 500 pages: pages collector 471 ms, templates 32 ms, every other collector < 80 ms; checks + report < 300 ms. Heap grows about 50 KB per page above the ~104 MB tsx/module baseline. No CPU or memory hotspot to fix.
- On public sites, wall time comes from the 300 ms politeness interval in `safeFetch`: 500 pages ≥ 2.5 min of fetch waits, plus sidecar render time for sampled pages. Waiting on fetches does not count as Worker CPU time.
- Sampling is every 100 ms, so short peaks can be missed. The 128 MB Worker limit applies to the in-app path. That path stores bodies in the evidence store as it goes, while the CLI also keeps `collected.json`, so the CLI figures overstate the Worker's footprint.
