## Decisions (no Ken input; documented defaults)

- **R1 after the code work orders.** The live budget is 3 CLI full-depth runs (one per site). Running them before WO-004 / 005 / 013 would have spent the budget on known false positives and left nothing for the reruns the ATs ask for, so each site runs once, on the fixed code; the first-pass record (`fork/reports/field-tests-3-5-first-pass-2026-11-23.md`) is the "before".

- **GoodGEO found a real false positive** outside the WO list: P6-09 counted `sameAs` only on types ending in "Organization", so a `Dentist` / `BikeStore` / any LocalBusiness subtype carrying the profiles read "Organization sameAs has 0". Fixed (`isOrganizationType`); also used by the SERP brand-name keys.
- **WO-004** measures text, not layout: the re-render compares visible text (word-set Jaccard ≥ 0.98, counts within 2 %). A blocked stylesheet that only moves things reads "same content" (ADR-033 §1). Each page takes its own measurement, else its template sample's; one finding per outcome (S1 changed / S4 unchanged / by type when not measured).
- **WO-005**: an uncrawled canonical target keeps the finding (checks do not fetch), except when the two URLs differ only in encoding (`%20` / `+`), which covers the aircor tag set.
- **WO-012**: the stage repository lets the report unit write its own `done` row on a `completed` run; every other late write is still dropped. Stored runs keep their `running` report rows (no backfill).
- **WO-014 cause**: quotes are not stored per call, so the failing quote cannot be replayed; the live aircor text prints curly apostrophes ("that’s the #1 reason", "Why We’re the Best"), which a model quotes straight. Normalised both sides: NFKC, curly quotes, dashes, ellipsis, case. Exact-substring rule otherwise kept.
- **WO-016 cause**: run `a3891e38` lighthouse unit 17:48:52–17:49:05 UTC (13 s for every URL), note "sidecar /lighthouse unreachable: Network connection lost." = the TCP connection dropped mid-request, i.e. the sidecar process went away. Watchdog log shows no restart then; the container was recreated at 19:50 UTC (B19 rebuild), so its log for that minute is gone. Most likely the sidecar stall guard (2 deadline misses in 10 min → `process.exit`, Docker restarts it) after the axe unit on heavy aircor pages. Fix: one retry per URL once `/health` answers again (≤ 90 s); Fix list cause "Speed checks did not run".
- **WO-011**: no scoring change; the Fix list Overall tile shows "N before the must-fix cap".
- **WO-009 (partial)**: per-check timing (`handbook.checks.timing`) and checks save time (`handbook.checks.save_ms`) are logged; run results are saved with multi-row inserts (chunked under D1's 100 bound parameters; one statement per table on Postgres). Crawl concurrency and parallel LLM checks not done this run; before / after timing needs an in-app rerun.
- `fork/scripts/run-query.ts` loads `.env.local` itself (like `handbook-audit.ts`) so read-only queries need no shell sourcing; `field-test.ts --preflight` no longer says "Over 100 URLs" for a site with 0 sitemap URLs.
