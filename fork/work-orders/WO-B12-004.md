# WO-B12-004: Test-only BadGEO sidecar on port 4778 (real audits stay strict)

- Batch: B12 · Class: LIGHT · Size: S
- Contracts: CONTRACTS_VERSION 1.7.0 (no change)
- Depends: WO-B12-003 (same image)

## Why

BadGEO `--sidecar` needs a sidecar that may reach the local fixture server (private network). The real sidecar must keep `HANDBOOK_SIDECAR_ALLOW_PRIVATE=0` (SSRF guard for live audits). Today this is BLOCKED-KEN ("restart the sidecar with compose.badgeo.yaml"), and an ad-hoc container `hb-sidecar-badgeo` was started by hand in B9/B10.

## Spec

- `fork/sidecar/compose.badgeo.yaml` defines a second service `sidecar-badgeo`: same build / image as `sidecar`, port `127.0.0.1:4778:4777`, `HANDBOOK_SIDECAR_ALLOW_PRIVATE: "1"`, `extra_hosts: ["127.0.0.1.nip.io:host-gateway"]`, same token variable, `restart: unless-stopped`, `init: true`, `ipc: host`. The `sidecar` service is untouched (no override of it).
- `fork/scripts/start-build.sh`: compose up uses both files (`-f compose.yaml -f compose.badgeo.yaml`) so both start; health wait + token check stay on 4777 (fatal); 4778 health is checked too but only warns.
- Remove the ad-hoc `hb-sidecar-badgeo` container if it exists (`docker rm -f hb-sidecar-badgeo`).
- Docs: `fork/sidecar/README.md`, `fork/RUNBOOK.md` (BadGEO with render: `--sidecar http://127.0.0.1:4778`), `badgeo-run.ts` header comment.
