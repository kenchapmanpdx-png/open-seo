# WO-B23-001: P3-04 — a missing canonical alone is S3, not S1

- Batch: B23 · Class: HEAVY · Size: S
- Contracts: none
- Depends: —
- Registry items: P3-04

## Red case (SUPPORTED: source read at `f1ce14b1`; no run)

- `checks/canonical-form.ts`: "Indexable pages without a canonical" calls `report()` with no effect argument → default `severity: "S1"`. `engine/s1-scope.ts` keeps S1 when the URL is indexable; `scoreItems` caps the total at 39.
- Google (consolidate-duplicate-urls, read 2026-11-24): canonical methods are recommended, none required; without one Google picks the canonical itself; a self-referencing canonical is recommended.
- `checks/hreflang.ts` `selfCanonical` already treats a missing canonical as self-canonical: the app holds two positions.

## Class

An optional consolidation signal is graded as an indexing failure. A site with unique URLs and no canonical tags cannot grade above F.

## Decision (default)

- Missing canonical on an indexable page → **S3**, `severityReason` "no canonical declared: Google chooses one itself; a self-referencing canonical is recommended, not required". Finding, fix text and item status (OPEN) stay.
- Every other P3-04 branch (canonical points elsewhere, paginated to page 1, tracking parameters, internal link forms) unchanged.
- "For Ken: say 'missing canonical stays S1' to revert." ADR-038 (addendum to ADR-034).
