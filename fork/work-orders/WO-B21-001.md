# WO-B21-001: a run that read no page is never graded, never "passed"

- Batch: B21 · Class: HEAVY · Size: M
- Contracts: additive `score.notGradedReason` (CONTRACTS_VERSION 1.11.0 → 1.12.0, ADR-036); no schema or migration change
- Depends: —
- Registry items: all (scoring); P0-xx collectors `pages`

## Red case (SUPPORTED, observed in the app)

- zmklaw.com, run `e8f77e8b` (2026-11-24). Banner: "The site could not be read". Details: "Grade A 100/100", "Every automated check passed". Collector `site-crawl` returned `unavailable` ("no page could be fetched", `collectors/site-crawl.ts`).
- WO-B20-010 fixed one consumer only: `unreadSiteReason` (`client/features/handbook/fixList.ts`) is read by `FixList.tsx`. Every other consumer reads `score.grade` / the findings list on its own.
- Cause of the "100": UNKNOWN. `engine/scoring.ts` returns 0 when no item is applicable, so an A means items ended PASS (SPECULATIVE: checks passing on empty input) or the stored grade differs from a live score. Step 1 finds out.

## Class

Zero evidence reads as a pass. A run's graded / not-graded state is derived in several places instead of once.

## Steps

1. **Red**: test at `buildReport` (`services/HandbookScore.ts`) with 0 page snapshots and `pages` collector `unavailable` (fixture from the zmklaw run's stored rows or a minimal one). Record which items are PASS (red output → `fork/runs/b21/wo001-red.txt`). Write the finding of this step in the report (which checks pass vacuously).
2. **Vacuous pass**: one rule in the item-status derivation (`engine/process-items.ts` / runner): an item whose check `requires` a collector that is `unavailable` is BLOCKED with the collector's reason, never PASS and never silently absent. Test per collector key in `requires` (table-driven over the check registry, so a new check cannot opt out).
3. **Single derivation of graded state**: `scoreReport` (`engine/report.ts`, where `grade` is set) adds `score.notGradedReason: string | null`. Not graded when `run.coverage.read === 0` or the `pages` collector is unavailable. `read === undefined` (stored pre-coverage runs) = graded, unchanged. `grade` and `final` stay numbers (old reports keep parsing); they are not shown when the reason is set.
4. **One reader**: `gradeView(score)` returns `{ kind: "graded", grade, final } | { kind: "not-graded", reason }`. Move every consumer to it: `ScoreCard.tsx`, `FixList.tsx` (also replace `unreadSiteReason` use), `FindingsTable.tsx` (empty state: no "Every automated check passed" unless pages were read and no item is BLOCKED by an unavailable collector), `HandbookRunsPage.tsx` (`run.grade`), `agency/overviewService.ts` + `ProjectOverview.tsx`, `export/markdown.ts`, `export/client-report.ts`, `mcp/tools.ts` (both sites), `HandbookService.ts` summary, `golden-score.ts`.
5. **Persisted grade**: `HandbookGradeRepository.saveRunScore` stores NULL grade / score for not-graded runs (columns already nullable; no migration). `listUngradedRuns` / `backfillGrades` must not re-pick them: second `ops backfill-grades` updates 0 rows.
6. Partial reads (pages read, some other collector `unavailable`): grade stays, existing "not final" banner stays, but the findings empty-state and exports never say "passed" for items BLOCKED by that collector.

## Guards

- `HandbookScore.test.ts` (entry point `buildReport`): 0 snapshots → `notGradedReason` set, no PASS item, `gradeView` = not-graded.
- One table-driven test over the consumers in step 4: given a not-graded report, none renders a letter, a number out of 100, or the words "passed" / "Every automated check".
- Source scan (like WO-B20-015 retry guard): `score.grade`, `score?.grade`, `.score.final` read outside `gradeView` and an allow-list (each entry with its reason) fails `pnpm test`; red = the current tree (list the hits).
- `backfillGrades` idempotence test (second call updates 0).
- Legacy: stored report without `coverage` → graded.
