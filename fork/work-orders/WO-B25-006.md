# WO-B25-006: BentoBox not recognised as a builder (P0-03)

- Batch: B25 · Class: HEAVY · Size: XS
- Contracts: none
- Depends: —
- Registry items: P0-03

## Red case (SUPPORTED: live, 2026-11-26)

- theogdenver.com, audit `907d0a17-ed1e-4f82-90b9-f69423fb1008`, finding F40 "Platform not identified": `No platform header, generator meta or builder script host found on the crawled pages.`
- Live: every page loads its theme, app and media from BentoBox hosts: `theme-assets.getbento.com`, `app-assets.getbento.com`, `assets-cdn-refresh.getbento.com`, `images.getbento.com`, `media-cdn.getbento.com`. No generator meta and no platform header.
- Repeats: none in the latest runs (only theogdenver.com is on BentoBox).

## Class

`checks/platform.ts` knows builders without a generator meta only by their script / media hosts (Showit, GoDaddy, Duda, Weebly, Jimdo …). BentoBox, a hosted restaurant builder, is missing, so the platform is "not identified". The LIMITED reasons that depend on the builder are then never applied.

## Steps

1. **Red test** (public entry point: the platform check, `checks/platform.test.ts`): a home snapshot whose scripts load from `theme-assets.getbento.com` and `app-assets.getbento.com` → today "Platform not identified". Save to `fork/runs/b25/wo006-red.txt`.
2. **Class fix**: add `{ test: /(^|\.)getbento\.com/i, platform: "BentoBox", builder: true }` to the host list (beside Showit). Check whether any builder-limited item needs a BentoBox wording; if none, record "BentoBox uses the generic builder wording".

## Guards

- The existing Showit / Weebly / Duda host tests still pass.
- A site that only embeds a BentoBox image (`images.getbento.com`) on one page, with another platform identified by header, keeps that platform (header signal wins, as today).

## Do not

- Add other builders not seen in a field run.
