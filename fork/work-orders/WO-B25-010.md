# WO-B25-010: Lazy-loaded images with a `data:` placeholder `src` are never probed (SUPP-20, image budget)

- Batch: B25 · Class: HEAVY · Size: S
- Contracts: none. `PageSnapshot.images[].dataSrc` already exists; `data-lazy-src` / `data-original` are read into that same field (first present of `data-src`, `data-lazy-src`, `data-original`). No new field → no `CONTRACTS_VERSION` bump.
- Depends: WO-B25-001 (same `images` derivation; build 001 first)
- Registry items: SUPP-20 (broken resources), P2-05 / image-weight budget (oversized images), P8-06 filename-alt (alt text)

## Gap (SUPPORTED: code read 2026-11-25, found while writing WO-B25-001)

- `engine/html-facts.ts` records `src` and `data-src` of each `<img>` (`dataSrc`); `data-lazy-src` and `data-original` are not read.
- `collectors/resources.ts` probes `img.src || img.dataSrc`. A lazy `<img>` whose `src` is a `data:` placeholder (or `about:blank`) has a non-empty `src`, so `dataSrc` is never chosen; `add()` then drops the `data:` URL (not http/https). The real image is never probed, so a broken lazy image is missed unless a `<noscript>` copy exists.
- `checks/image-weight.ts` `budget()` matches an oversized resource to its `<img>` by `src` only, so a lazy image never gets its width/height byte budget.
- `checks/a11y-markup.ts` `fileAlt()` already uses `dataSrc ?? src` (filename-alt works for lazy images, but prefers `dataSrc` even when `src` is http).

## Class

## Guards

- An http `src` wins over `data-src`: `<img src="https://example.com/a.png" data-src="https://example.com/b.png">` probes `a.png` only.
- The same image as a lazy `<img>` and as a `<noscript>` copy (`src` = the `data-src` URL) is probed once and reported once with both pages as sources (resources are keyed by URL).
- `<img src="" data-src="…">` behaves as today (already probes `data-src`).
- Mixed-content (`checks/link-hygiene.ts`) and header probes (`collectors/headers-collector.ts`) keep reading `src`; not changed in this WO.
