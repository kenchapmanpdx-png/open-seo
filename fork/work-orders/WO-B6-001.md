## Spec

- `encryptKey(value)` / `decryptKey(value)`: `symmetricEncrypt`/`symmetricDecrypt` from `better-auth/crypto` with `(await getAuth().$context).secretConfig`. Always encrypt (unlike upstream `tokenCrypto`, which skips when `encryptOAuthTokens` is off): these are third-party API keys.
- Repository: `getBingKey(orgId)`, `setBingKey(orgId, key)`, `getByokKey(orgId, provider)`, `setByokKey(orgId, provider, key)`, `deleteByokKey`. Getters fall back to env (`BING_WEBMASTER_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `PERPLEXITY_API_KEY`) only when `AUTH_MODE` is the local single-tenant mode (read `getAuthMode`); hosted modes never fall back.
- Return `{ configured: boolean, source: 'org' | 'env' | null }` to any client-facing caller; the key itself never leaves the server.

## Conventions

- Tables already exist (B5 R4a): import them from `@/db/integrations-tables` (provider-aware); never from a dialect file. Repository → service → server fn (AGENTS.md). Every query is scoped by `organization_id` (project rows) or joins to a scoped parent. Server fns live in the feature folder (`functions.ts`, pattern: `src/server/features/handbook/functions.ts`); repository tests use a real SQLite test DB (pattern: `src/server/features/ai-visibility/aiVisibilityTestDb.ts`).
