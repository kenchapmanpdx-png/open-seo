# WO-B12-003: Sidecar recovers by itself when it stalls; engine never waits forever

- Batch: B12 · Class: LIGHT · Size: M
- Contracts: CONTRACTS_VERSION 1.7.0 (no K3 request / response change). Sidecar image 1.2.0 → 1.2.1.
- Depends: —

## Read first

- `fork/reports/B10.md` run 54 and `fork/reports/B11.md` R4 incidents: ~5 h after start the sidecar stopped making network requests (net counter flat, ~22 % CPU); a bluetree render waited 40 min; `docker restart sidecar-sidecar-1` fixed it.
- `fork/sidecar/server.ts` (`limiter`, `createSidecar`, `main`), `fork/sidecar/render.ts`, `fork/sidecar/compose.yaml` (`restart: unless-stopped`, `init: true`)

## Spec

Sidecar (`fork/sidecar/server.ts`):

- Every engine task (render, axe, Lighthouse) gets a hard deadline: render / axe = request timeout + 60 s (default 120 s), Lighthouse = 240 s. Past it → HTTP 504 `{ error: "deadline" }` for that request.
- Stall rule: 2 deadline misses within 10 min, or 1 task still running at 2× its deadline → log one line and `process.exit(1)` once in-flight responses are written. Docker restarts the container (`restart: unless-stopped`), same token and config.
- Browser recycle: after `HANDBOOK_SIDECAR_RECYCLE_AFTER` tasks (default 500) and no task in flight, close and relaunch Chromium (prevents the slow 5-hour degradation).
- Log one line per stall / recycle (time, task kind, deadline). `/health` unchanged (K3 frozen).
- `SIDECAR_VERSION` and `compose.yaml` image tag → 1.2.1.

Engine (sidecar client):

- Client-side timeout per call = sidecar deadline + 30 s. Timeout or 504 → that page / item BLOCKED `sidecar timeout`, run continues.
- 3 consecutive timeouts in one run → sidecar marked unavailable for the rest of the run (render / axe / Lighthouse items BLOCKED `sidecar unavailable`, FULL-READ §8), wait 60 s, probe `/health` once; healthy → resume.

## Tests

- Sidecar unit: fake engine that never resolves → 504 after the deadline; second miss → exit hook called (inject `exit` for the test).
- Engine unit: client times out → BLOCKED, run completes; 3 in a row → unavailable path.
