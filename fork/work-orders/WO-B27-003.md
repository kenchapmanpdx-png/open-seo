# WO-B27-003: scope is decided before the run, inside the app

- Batch: B27 · Class: HEAVY
- Source: Project chat instructions 2026-11-28 (B26 WO-091 run 108: evolvedmechanical.com no audit; antiquecandleco.com audit `5cdbb86c` capped; wellnessforzebras.com llm budget); owner order 2026-11-28 "no failed starts, no silent caps; find each cause and fix it".

- Red case: antiquecandleco.com scope was chosen by a CLI preflight and a rule in a chat instruction; the app itself showed "Whole site (up to 500 pages)".
- Fix:
  1. One effective page limit per run, computed once (`services/runScope.ts`): the site audit limit and the Handbook limit resolve to the same number; `capNotes.ts` and the UI quote that one number. The two limits must never differ within a run.
  2. Check a site runs the preflight (move the logic of `field-test.ts --preflight` into a service): sitemap URL count in total and by first path section, plus parameter-URL share.
  3. Count ≤ limit → whole site. Count > limit → automatic core scope: leave out whole sections, largest archive-type first (`/blog`, `/blogs`, `/news`, `/tag`, `/category`, `/author`, date archives, paginated lists), then the largest remaining section, until the in-scope count is ≤ 90 % of the limit. Deterministic order; ties by section name.
  4. The page shows the decision before the run starts: pages in scope, sections left out with their counts, the limit. The user can change it; unattended runs take the default. Stored on the run and printed at the top of the report.
  5. No sitemap → state "no sitemap; scope is decided while crawling" and apply WO-004 rules.
  6. Default limit stays as today. For Ken: say "ask me before leaving sections out" to make step 3 a required choice.
- Guards: a 34-page site still runs whole with no scope message beyond the page count. A site of exactly the limit runs whole.
