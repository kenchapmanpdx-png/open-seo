# WO-B21-003: sitemap `<loc>` scheme is one finding, owned by P3-19

- Batch: B21 · Class: HEAVY · Size: S
- Contracts: none (no contract, schema or migration change)
- Depends: —
- Registry items: P3-12, P3-13, P3-19 (CRAWL)

## Red case

- aweandorderorganizing.com (https site). Sitemap lists 7 pages under `http://` (Semrush "HTTP URLs in sitemap.xml for HTTPS site" ×7).
- App: P3-13 note "sitemap 7 · crawled 8 · both 0 · sitemap-only 7 · crawled-only 8". P3-12 findings "Sitemap lists URLs that redirect or do not return 200" (7 URLs) and "Indexable pages missing from the sitemap" (8 pages) both fire on the same pages. P3-19 "OK: `<loc>` host = canonical host" (host only).
- Code: `normalizeUrl` (`checks/support.ts`) keeps the scheme. `inventoryIssues` (`checks/url-inventory.ts`: `locSet`, `byUrl`, the `unlisted` loop) and `crawl-coverage.ts` P3-13 (`locs`, `crawledSet`) compare `http://x/a` and `https://x/a` as different pages.
- Mechanism of the double count: SPECULATIVE until step 1 reproduces it (the https pages are absent from `locSet`, so each is "missing" while its http `<loc>` is reported as a redirect).

## Class

A sitemap-vs-crawl comparison that is scheme-sensitive reports one defect (wrong scheme in `<loc>`) as two or three (redirects, missing pages, no overlap).

## Decision (default)

- One defect, one finding: the scheme difference is owned by **P3-19** ("Sitemap `<loc>` scheme differs from the canonical scheme", S3, same severity as the host finding). P3-12 `status` skips a `<loc>` whose only difference from its final URL is the scheme; P3-12 `unlisted` and P3-13 counts match pages by a scheme-insensitive key. "For Ken: say 'scheme stays in P3-12' to revert."

## Steps

1. **Red**: `url-inventory.test.ts` at the check entry: https site, crawl holds the https pages (plus the http variants as 301 snapshots if the crawler adds them), sitemap holds the http forms → today: `status` + `unlisted` findings and no scheme finding. `crawl-coverage.test.ts`: same fixture → `both 0`. Save red output.
2. **Class fix**: `sitemapKey(url)` in `checks/support.ts` (fragment stripped like `normalizeUrl`, scheme folded, host unchanged: www vs bare stays P3-19's host rule). Use it for set membership in `inventoryIssues` (`unlisted`, `locSet`) and `crawl-coverage.ts` (`locs`, `crawledSet`, `both`, `sitemapOnly`, `crawledOnly`). `normalizeUrl` stays scheme-sensitive for everything else.
3. **P3-19**: canonical origin = scheme + host of the home page's canonical (fallback: run origin). Finding lists the `<loc>` whose scheme differs; evidence = sitemap listing (existing `listing`). P3-19 PASS text states scheme and host.
4. P3-13 note adds "N `<loc>` on another scheme (see P3-19)" when N > 0.
5. BadGEO: one `<loc>` with `http://` in a sitemap the site already serves (reuse `sitemap-build.xml`; no new sitemap unless that file is asserted elsewhere); `_expect.json` asserts `P3-19:S3` and no extra P3-12 on that URL.

## Guards

- `url-inventory.test.ts`: 3 http `<loc>` on an https site → exactly one P3-19 finding listing 3 URLs; no `unlisted`, no `status` for them. Control: a page truly absent from the sitemap still gives `unlisted`; a `<loc>` that really 404s still gives `status`; an off-host `<loc>` still gives the host finding.
- `crawl-coverage.test.ts`: same fixture → `both 3`, `sitemap-only 0`.
- Source scan: `locs` / `crawledSet` style comparisons in `checks/` use `sitemapKey` (one pattern list, like the pagination scan in `pagination.test.ts`); red = current tree hits.

- Replay: any golden whose expected findings include "Sitemap lists URLs that redirect…" because of http `<loc>` moves with a ledger note; otherwise Δ 0.
