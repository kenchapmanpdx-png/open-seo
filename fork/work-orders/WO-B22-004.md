# WO-B22-004: round 3: three larger sites, matched scope

- Batch: B22 · Class: chat-side + HEAVY · Size: L

- Depends: WO-B21-090, WO-B22-001, WO-B22-005
- Status: BLOCKED-KEN. The Semrush half runs in Ken's Project chat with the Semrush connector (account rules below); the autopilot has no Semrush access. Ken's "go" in the Project chat starts it. The build half is `field-test.ts` on the CSVs the chat commits.

## Why

- Rounds so far used sites under 50 pages (size gate, `fork/MAINTENANCE.md` M6, WO-B21-090). Larger sites ran in B18 / B19 but with unmatched scopes (aircorheatingcooling.com app 238 pages vs Semrush 23; nwpersonaltraining.com 131 vs 60; valentinecoffeeco.com 61 vs 20), so their misses mean little. Platforms and size classes where real client sites live (WordPress, Shopify, 100+ pages) are covered only by those runs.

## Method (matched scope, apples to apples)

1. Pick 3 unaffiliated sites (not Ken's, not previously tested): one WordPress, one Shopify, one any-platform with a blog or news section. Pre-flight each: `field-test.ts <site> --preflight` (sitemap `<loc>` count per section), robots.txt, platform. Reject sites with a link trap or a login wall in scope.
2. **Pre-register the scope in the report before any run**: 2–3 sections (path prefixes) summing 40–90 sitemap URLs. App side: Check a site "Leave out sections" / `--exclude`; Semrush side: crawl masks (`/path/`, not `/path/*`). Same URL set on both sides by construction.
3. **Size gate (extended)**: after both runs, app pages read within ±10 % of Semrush pages read, app Details shows no 50-page-limit note, Semrush finished below its page limit. Otherwise rescope and rerun; never compare unmatched crawls.
4. Compare on the **intersection** of URLs both tools read; URLs read by one tool only are listed, not scored.
5. Verdicts per M6 (live check before every verdict; each `fixed` names its red case). Misses go to a B23 queue as rows, each with red case → class fix → guard → rerun; this WO closes when every row has a verdict.
6. Semrush account rules (all calls in the one chat session, no sub-agents): ≤ 2 concurrent crawls, polls ≥ 10 min apart, delete the projects when finished. Semrush connector `issue_details` returns at most 50 rows per issue: record the true total and the rows retrieved in the report.
