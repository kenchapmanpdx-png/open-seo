# WO-B23-006: P9-01 AI-bot policy split — an HTTP 429 provoked by the audit's own requests is not a block

- Batch: B23 · Class: HEAVY · Size: S
- Contracts: none
- Depends: —
- Registry items: P9-01

## Red case (SUPPORTED: live, B21 run 100)

- aweandorderorganizing.com, `fork/runs/aweandorderorganizing.com/field-2026-11-24` (run 100): F30 "AI-bot policy split: robots.txt allows crawlers the server blocks" lists CCBot, meta-externalagent, DuckAssistBot, MistralAI-User, cohere-ai as "HTTP 429".
- Live 2026-11-25, one request each 3 s apart: CCBot 200, meta-externalagent 200, DuckAssistBot 200. The 429s are Cloudflare rate limiting of the policy-map burst (`collectPolicyMap`, one request per token ≥ 300 ms apart, after the probe burst), not a per-bot policy.

## Class

`ai-bot-policy.ts` `BLOCK_STATUS` counts 429 as a block. A rate-limit answer says "too many requests", not "this bot is refused".

## Decision (default)

- `collectPolicyMap`: on 429, wait (Retry-After, capped like ADR-035 crawl retries) and fetch that token once more through the existing retry primitive; the row keeps the second answer.
- `ai-bot-policy.ts`: a row still 429 after the retry is not a policy split; it is listed in the PASS / BLOCKED note as "rate-limited, not judged".
- For Ken: say "429 counts as a block" to revert.

## Guards

- Collector test: 429 then 200 → row status 200; 429 twice → row 429.
- Check test: 429-only rows → no policy-split finding, note names the tokens.
- Rerun aweandorderorganizing.com: F30 lists only Bytespider (HTTP 403, live 403 to be re-checked).

## Do not

- Change bot parity (P9-01 S1/S2, ADR-037) or the probe pacing (ADR-035).
