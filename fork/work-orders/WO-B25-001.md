# WO-B25-001: `<noscript>` tracking pixel reported as a broken image (SUPP-20)

- Batch: B25 · Class: HEAVY · Size: S
- Contracts: none
- Depends: —
- Registry items: SUPP-20

## Red case (SUPPORTED: live, 2026-11-26)

- nwpersonaltraining.com, audit `a6af196e-206b-4af9-8bd3-d49822eff223`, finding F19 (S2) "Image returns an error on 78 pages": `https://www.facebook.com/tr?id=1266839488241493&ev=PageView&noscript=1 — no answer; used on 78 page(s)`.
- Live: that URL answers HTTP 200, `content-type: text/plain`, 0 bytes. Markup on every page: `<noscript><img height="1" width="1" style="display:none" src="https://www.facebook.com/tr?id=…&noscript=1" /></noscript>` (Meta pixel fallback), not a content image.

## How the engine reads images today (SUPPORTED: code read 2026-11-25)

- `engine/html-facts.ts` pushes every `<img>` it meets, including those inside `<noscript>` (htmlparser2 parses `<noscript>` children as elements; `SKIP_TEXT` only skips their text). It records `src` and `data-src` (`dataSrc`) of the same element.
- `collectors/resources.ts` probes `img.src || img.dataSrc`. A lazy-load `<img>` whose `src` is a `data:` placeholder drops out (`data:` is not http/https) and its `data-src` is never tried, so the `<noscript>` copy is then the only http source of that image.
- Stored raw HTML of every run where SUPP-20 fired, plus bluebonnetroofs.com (2026-11-25): `<noscript>` images matching a tracking-pixel pattern (`width="1"` or `height="1"`, or inline `display:none`) appear only on nwpersonaltraining.com (78 pages, Meta pixel). bluebonnetroofs.com (Showit, audit `cacb82a9`) holds 15 real content images only inside `<noscript>` (`<img src="//static.showit.co/400/…/bluebonnet_roofs_logo_png-02.png" class="se-img" alt="…">`), so skipping every `<noscript>` image would drop real images from SUPP-20 and the alt / dimension checks.

## Class

A `<noscript>` tracking beacon is probed as a content image; a beacon host that drops bot requests is reported as a broken image on every page.

## Steps

1. **Red test** (public entry point: page facts → resources collector → `resource-status` check, as in `checks/resource-status.test.ts`): a page with `<noscript><img height="1" width="1" style="display:none" src="https://www.facebook.com/tr?id=1&ev=PageView&noscript=1"></noscript>` whose probe returns no answer → today a SUPP-20 "Image returns an error" finding. Save the output to `fork/runs/b25/wo001-red.txt`.
2. **Class fix** at `engine/html-facts.ts` `images`: skip an `<img>` inside `<noscript>` only when it matches the tracking-pixel pattern: `width` = 1 or `height` = 1 (attribute, or inline style `width:1px` / `height:1px`), or inline `display:none` / `visibility:hidden`. Every other `<noscript>` image stays. For Ken: say "probe noscript pixels" to revert.
3. List every finding on the eight goldens and on bluebonnetroofs.com that changes (expected: the Meta pixel only, in SUPP-20 and the "images without dimensions" counts).

## Guards

- Showit lazy pattern stays: `<noscript><img src="https://static.showit.co/…/logo.png" alt="Logo"></noscript>` returning 404 still opens SUPP-20 (guard test, built from the bluebonnetroofs.com markup).
- A visible `<img src>` returning 404 still opens SUPP-20 (salonvata case).
- An `<img>` outside `<noscript>` on a tracker host that fails is still reported (the rule is `<noscript>` + pixel pattern, not a host allowlist).

## Do not

- Skip all `<noscript>` images, or add a tracker-host allowlist.
- Change SUPP-20 severity, the 403 retest rule, or the `src || dataSrc` order in this WO (record the `data:`-placeholder gap in the report as an observation).
