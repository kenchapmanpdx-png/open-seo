# WO-B25-001: `<noscript>` tracking pixel reported as a broken image (SUPP-20)

- Batch: B25 · Class: HEAVY · Size: S
- Contracts: none
- Depends: —
- Registry items: SUPP-20

## Red case (SUPPORTED: live, 2026-11-26)

- nwpersonaltraining.com, audit `a6af196e-206b-4af9-8bd3-d49822eff223`, finding F19 (S2) "Image returns an error on 78 pages": `https://www.facebook.com/tr?id=1266839488241493&ev=PageView&noscript=1 — no answer; used on 78 page(s)`.
- Live: that URL answers HTTP 200, `content-type: text/plain`, 0 bytes. It is the Meta pixel's `<noscript><img height="1" width="1" style="display:none" src=…></noscript>` fallback, not a content image.
- Repeats: SPECULATIVE. No other latest run carries this URL (salonvata's SUPP-20 hit is a real 404 logo). Any site with the Meta / LinkedIn / TikTok noscript pixel is exposed.

## Class

`collectors/resources.ts` collects every `<img src>`, including images inside `<noscript>`, which only render with JavaScript off. Tracking beacons there are sent to `fetchOffsite`, and a beacon host that drops or rate-limits bot requests is reported as a broken image on every page.

## Steps

1. **Red test** (public entry point: the resources collector + `resource-status` check, as in `checks/resource-status.test.ts`): a page whose only image is `<noscript><img height="1" width="1" style="display:none" src="https://www.facebook.com/tr?id=1&ev=PageView&noscript=1"></noscript>` and whose probe returns no answer → today a SUPP-20 "Image returns an error" finding. Save the output to `fork/runs/b25/wo001-red.txt`.
2. **Class fix** at the one derivation point (`engine/html-facts.ts` `images`, which `collectors/resources.ts` reads via the page snapshots): skip `<img>` elements inside `<noscript>`. Default: skip all of them, not only known tracker hosts; they are never shown with JavaScript on. For Ken: say "probe noscript images" to revert.
3. `images` also feeds the alt-text and image-dimension checks. List every finding on the eight goldens that changes (expected: tracker pixels only, in SUPP-20 and in the "images without dimensions" counts).

## Guards

- A visible `<img src>` returning 404 on the same page still opens SUPP-20 (true case kept).
- An `<img>` outside `<noscript>` pointing at a tracker host that fails is still reported (the fix is the `<noscript>` scope, not a host allowlist).

## Do not

- Add a tracker-host allowlist instead of the `<noscript>` rule.
- Change SUPP-20 severity or the 403 retest rule.
