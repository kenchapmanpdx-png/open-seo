# WO-B27-001: a site that refuses the app's crawler name is still read

- Batch: B27 · Class: HEAVY
- Source: Project chat instructions 2026-11-28 (B26 WO-091 run 108: evolvedmechanical.com no audit; antiquecandleco.com audit `5cdbb86c` capped; wellnessforzebras.com llm budget); owner order 2026-11-28 "no failed starts, no silent caps; find each cause and fix it".

- Red case: evolvedmechanical.com (Section 1).
- Class: every fetch identifies as `OpenSEO-Handbook/1.0` (`engine/safe-fetch.ts`). A firewall that drops unknown crawler names ends the run before it starts. `collectors/probe.ts` already retests a 403 as a browser for links (`browserRetest`); the site's own pages have no such step.
- Fix:
  1. `verifyWebsite`: app user-agent fails (connection closed, reset, timeout, 403, 406, 429, empty 200) → one retest with `BROWSER_UA`. Browser answers → the site is "reachable as a browser only"; the check passes and the run is created with that mode stored on the run.
  2. In that mode the run's page fetches use `BROWSER_UA`. robots.txt is still read and obeyed for `OpenSEO-Handbook` and `*`. Per-host pacing unchanged. Bot-parity (P9-01) keeps its own per-bot user-agents.
  3. A site that switches mid-run (first N page fetches refused for the app user-agent, home page answered) gets the same retest once, then the mode for the rest of the run. Not per URL.
  4. The report states the mode at the top: "This site refuses the app's crawler name; pages were read as a browser." One info line, no severity, no score effect.
  5. Default: automatic. For Ken: say "never read as a browser" to make it a refusal with a clear message instead.
- Guards: a site that answers the app user-agent is never read as a browser. A site whose robots.txt disallows the app is not read (existing rule). A site that refuses both user-agents is not retried further.
- Do not: rotate user-agents, add proxies, or retry in bursts.
