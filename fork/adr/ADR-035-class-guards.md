# ADR-035: Class guards for field-test defect classes (B20)

- Status: accepted (run 93; (c) and (e) done run 95)
- Date: 2026-11-24 · Batch: B20 · `fork/batches/B20-heavy-cap-scope-speed.md` (WO-B20-015)

## Context

Field tests 6–8 (samanthaco.ca, theogdenver.com, bluebonnetroofs.com) showed defects that were classes, not instances: one malformed href stopped eleven checks, a transient storage 520 lost four speed measurements, a severity rule ignored what the linked URL answers, a glued host reached the engine. [Ken 2026-11-23] "engineer the fixes so these don't happen again": each class gets a guard that fails the build.

## Decision

| Class                               | Fix (shared)                                                                                                                                                                  | Guard                                                                                                                                                                                                                                                    |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| (a) one bad value kills a check     | `checks/support.ts` `parseUrl` / `pathOf` / `bareHost` (undefined / "" on a bad URL), `siteUrl` / `originUrl` for the run origin; every `checks/` call site moved to them     | `checks/hostile-inputs.test.ts`: every registered check runs on malformed hrefs / src / canonical / hreflang / sitemap `<loc>` / robots `Sitemap:` / headers / JSON-LD / probe URLs and must finish; and no `new URL(` in `checks/` outside `support.ts` |
| (b) silent incomplete runs          | —                                                                                                                                                                             | `badgeo-run.ts` and `golden-score.ts` exit 1 on any item noted `check error` / `check contract violation`; the Fix list already shows "This grade is not final" for render failures                                                                      |
| (c) transient infrastructure errors | `engine/transient-retry.ts` `fetchWithRetry`: 429 / 5xx / network error, 3 tries, 400 ms doubling                                                                             | unit test per call-site class (below)                                                                                                                                                                                                                    |
| (d) severity out of proportion      | ADR-034 table (`engine/s1-scope.ts` `PAGE_SCOPED_S1` / `ACCESS_S1`)                                                                                                           | `contractViolation`: an S1 finding on an item in neither list blocks the item ("has no ADR-034 S1 entry"); `s1-scope.test.ts` fails when an S1-default item is unclassified; `golden-score` prints a capped grade and the finding(s) that capped it      |
| (e) finding says more than evidence | P3-08 / P3-07 `urls` = linking pages (targets in the detail); P4-09 title names the tags only when every page lacks the same ones                                             | unit tests at the checks; the general contract test (urls ⊆ pages read, title vs detail) is open                                                                                                                                                         |
| (f) bad input reaches the engine    | `verifyHandbookWebsite` (upstream `domainField` Zod + SafeFetch DNS policy + one home-page fetch) runs before Check a site writes a project or a run                          | `services/verifyWebsite.test.ts` (spaces, no TLD, private IP, IP literal, glued hosts) and `checkSite.test.ts` (nothing created when the site does not answer)                                                                                           |
| (g) field-test procedure            | `fork/MAINTENANCE.md` M6 rules: pre-flight recorded, valid run only (0 check / collector errors), live check before a verdict, every `fixed` names its red case and its guard | the ledger (`field-test.ts --close`)                                                                                                                                                                                                                     |

Retry call sites (c). One primitive, `engine/transient-retry.ts` `withRetry(attempt, policy)`: a call site states only its policy (which results are transient, tries, the wait before the next try; the wait may stop the retry). Run 95 moved every Handbook retry loop onto it:

| Call                                       | Policy (tries · transient · wait)                                                       | Test                                        |
| ------------------------------------------ | --------------------------------------------------------------------------------------- | ------------------------------------------- |
| Evidence store upload (Supabase)           | `fetchWithRetry`: 3 · 429 / 5xx / network error · 400 ms doubling                       | `supabase-evidence-store.test.ts` 520 → 200 |
| Sidecar `/render`, `/lighthouse` (restart) | 2 · "unreachable" · wait for `/health` ≤ 90 s (stop when it never answers)              | `sidecar-effects.test.ts`                   |
| Link / resource / outbound probes          | 2 · no answer, 429 / 502 / 503 / 504 · 2 s (a site's own server: never a burst)         | `probe.test.ts`                             |
| Sitemap fetch                              | 2 · 5xx · `SITEMAP_RETRY_MS`                                                            | `fetch-collectors` tests                    |
| URL-variant probes                         | 2 · 429 · `Retry-After` (capped 15 s, default 10 s)                                     | `fetch-collectors` tests                    |
| Crawl interstitial (challenge page)        | 2 · challenge detected · `INTERSTITIAL_RETRY_MS`                                        | `interstitial.test.ts`                      |
| Competitor fetch (SERP originality)        | 2 · not HTTP 200 · none                                                                 | `serp-originality` tests                    |
| LLM (OpenRouter)                           | AI SDK `maxRetries` with `retry-after` (ADR-019; library policy, not a Handbook loop)   | `llm/judge` tests                           |
| DB save                                    | workflow step retries (Cloudflare Workflows step config; one transaction per save, B20) | —                                           |

Not retries, kept on purpose: the render throttle and the sidecar circuit breaker (`sidecar-per-url.ts`, state shared across pages), the per-host pacers (`safe-fetch.ts`, `bot-fetch.ts`), timeout races. Guard: `engine/transient-retry.test.ts` (withRetry: transient then success = result kept; last result after the last try; thrown errors only with `retryThrown`) and a source scan: a Handbook file that waits with `setTimeout(` outside that allow-list (each entry with its reason) fails `pnpm test`. Red: the run-94 tree fails it with 4 files (`fork/runs/b20/retry-guard-red.txt`).

(e) finding says more than its evidence (run 95): `fork/scripts/lib/finding-contract.ts` `findingContractIssues(report, collected)`, run by `badgeo-run.ts` and `golden-score.ts` (exit 1 on any issue): every URL in `urls` was fetched by the run; a links finding lists the linking pages (crawled), the targets stay in the detail; "(n pages)" in a title equals `urls.length`; "Pages missing a, b" names only tags the detail shows; a finding on robots.txt / sitemap / llms.txt that answered non-200 says the status. Unit test `finding-contract.test.ts` (`pnpm exec vitest run --root fork/scripts lib/finding-contract.test.ts`). Red: the B19 salonvata golden run (`b19r92`, before WO-014 b) fails with P3-08 listing link targets (`fork/runs/b20/finding-contract-red.txt`); 22 other stored runs (BadGEO r6, eight goldens' B19 runs, field runs) pass.
