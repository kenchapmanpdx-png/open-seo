# ADR-029: Novice layout — Fix List, SEO / GEO / AEO tags, plain words, fork nav

- Status: accepted
- Date: 2026-11-20 · Batch: B14 · Spec: `fork/NOVICE-UI.md`

## Context

- Two audits (Site Audit, Handbook), build codes on every result page (S1–S4, F-codes, OPEN, BLOCKED, Tier, Mode), no SEO / GEO / AEO grouping, 15 sidebar items, a dashboard that does not lead to "check my site" (NOVICE-UI N1–N6, re-verified B14 R1 run 76).
- The registry has no category field; `tags` holds tier / audit / review / gate / buildPhase.
- SUPP `class` values are `deterministic` / `render` / `llm` (not CRAWL / HEADERS / ROBOTS / JSONLD as the spec's §4 assumed).

## Decision

1. Fix List is the default run view. `/p/$projectId/handbook/$runId` opens on "Fix list"; the B13 views stay under a "Details" tab. The Handbook index shows the latest completed run's Fix List, then "Past checks".
2. Tags live in `src/server/features/handbook/registry-tags.json`, generated by `fork/scripts/registry-tags-draft.ts` (phase rules → text rules → SUPP class fallback → override list with a one-line reason). `--check` fails CI-style when the JSON drifts. Values only `SEO` / `GEO` / `AEO`; `[]` = process item ("General", outside the three scores).
3. SUPP class fallback (spec §4 adapted to the real class values): `deterministic` / `render` → SEO; `llm` → SEO, AEO; applied only when no text rule fires.
4. Category score = mean `ITEM_SCORE` over applicable items carrying the tag × 100, rounded to an integer; capped at `S1_CAP` when an OPEN / PARTIAL item carrying the tag links a non-LLM S1 finding (the overall rule, restricted to the tag); `null` with no applicable item. Overall score and grade unchanged. Finding `categories` = union of its items' tags, in SEO, GEO, AEO order.
5. Computed by one pure function `withCategories(report)` (`engine/categories.ts`) called after scoring in both report builders (`buildReportJson`, `buildReport`), so stored runs gain the fields without a schema change or backfill.
6. Plain words: one map `src/client/features/handbook/labels.ts`; codes only inside "Details" disclosures.
7. Fork nav: `src/client/navigation/forkNav.ts` `getForkNavGroups(projectId, all, aiNavItem)`; a 2-line hook in upstream `getProjectNavGroups` (A12). Items the fork map does not know go to "More", so upstream pages added after a rebase stay reachable.
8. AI Search page fallback rule (spec §5): a tab renders the upstream feature component only when that component takes its route state as props / reads no route-bound `useSearch` / `Route.useParams`; otherwise the tab is a link card to the upstream page. All three fall back → no tab page, the "AI Search" group lists the three upstream routes under the plain names.
9. "Check a site" (`/handbook/check`) reuses `startAudit` (`renderJavaScript: false`) and the B13 Handbook-after-finalize path (ADR-026); it never starts the Handbook run itself.

## Consequences

- Contracts 1.8.0 (additive, optional `categoryScores`, finding `categories`); sidecar `contractsVersion` follows after `ops sidecar` rebuild.
- Two upstream hooks (A12, A13) and one text edit (A14) add to the rebase surface; logged in `fork/UPSTREAM-EDITS.md`.
- Tags are a judgment call; scores overlap when an item carries several tags. Not comparable with other tools' scores.

## Alternatives

- Tag field inside `registry.json`: rejected — the registry is generated from the verbatim handbook (`handbook-sync`); a side file keeps sync diff-free.
- Category scores stored on the run row: rejected — needs a schema change (B14 forbids); computing on read costs nothing.
- Replacing the run page: rejected — spec §0 "nothing removed".
